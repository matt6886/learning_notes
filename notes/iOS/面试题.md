## Swift面试题

### WHY Swift not ObjC?

Swift相对于Objective-C，主要优势在于：

* 类型安全更强
* 内存更安全（避免空指针）
* 语法更简洁现代化
* 性能更高（接近C++）
* 更好的函数式编程支持
* 更容易维护的大型项目能力

**核心对比**

* 类型更安全

```swift
id obj = @"Hello"
obj = @123 // 完全没问题，编译不会报错，运行时才崩溃。

var str: String = "Hello"
str = 123 // 错误在编译器就发现，适合大型项目
```

* Optional（解决空指针问题）

```swift
NSString *str = nil
NSLog(@"%@", str) // 不会崩溃，但逻辑容易出错。

NSArray *arr = nil
[arr addObject: @1] // crash

// Swift必须解包才能处理, 强制处理nil，避免90%空指针崩溃
var str: String? = nil
print(str) // Optional(nil)
if let str = str {
  print(str)
}
```

* 内存管理（ARC更安全）

* 语法更现代（开发效率）

```swift
NSString *str = [NSString stringWithFormat:@"%@ %@", a, b];
let str = "\(a) \(b)" // 更像脚本语言，更少样本代码
```

* 性能更高

```swift
// Swift静态类型，struct + value type，编译优化更强
struct User {
    var name: String
}
// 栈分配，copy-on-write,无锁线程安全

// Objc: 全是引用类型，堆分配（慢），多线程需要加锁。
@interface User : NSObject
@end
```

* 面相协议编程（POP）

```swift
protocol Flyable {
  func fly()
}
// Swift 中struct和class都支持，并且支持extension默认实现。

@protocol Flyable
@end
// Objc主要用于class，没有默认实现（早期）
```

* 函数式编程能力

```swift
// Swift
let nums = [1, 2, 3]
nums.map { $0 * 2 }
// Objc 写法非常复杂
```

Swift的核心优势不是语法糖，而是通过类型系统、Optional和值类型，把大量运行时问题提前到编译期间解决，从而提供安全性和可维护性。这对于大型iOS项目尤其重要。

### 请比较 Swift 中的结构体和类的主要区别？class 和 struct 的区别.

在Swift中，class和struct的关键区别：

* struct是值类型（赋值时拷贝）
* class是引用类型（共享引用）

这就导致了在内存管理、可变性、继承以及线程安全性方面存在差异。

**核心区别**

* 值类型 vs 引用类型

```swift
struct User {
    var name: String
}

var u1 = User(name: "Tom")
var u2 = u1
u2.name = "Jerry"

print(u1.name) // Tom ✅
// u2是拷贝，修改不会影响原来的对象

class User {
    var name: String
    init(name: String) {
        self.name = name
    }
}

var u1 = User(name: "Tom")
var u2 = u1
u2.name = "Jerry"

print(u1.name) // Jerry ❗
// u2和u1指向同一个对象
```

* 内存分配

| **类型** | **存储**   |
| -------- | ---------- |
| struct   | 栈（通常） |
| class    | 堆         |

struct更快，class需要ARC管理。

* 是否支持继成

struct不支持继承，而class支持继承。struct更轻量，class更适合复杂层级。

* 可变性

```swift
struct User {
    var name: String
}

let user = User(name: "Tom")
// user.name = "Jerry" ❌
// let修饰后整体不可变

let user = User(name: "Tom")
user.name = "Jerry" // ✅
// 引用不变，但内部可变
```

* identity vs 值

```swift
class有identity
u1 === u2 // 判断是否同一个对象

struct没有identity
u1 == u2 // 只能比较值
```

* 内存管理

```swift
class需要ARC，struct不需要，自动释放。class有循环引用问题，而struct不会。
```

* copy-on-write

```swift
let user = User(name: "Tom")
user.name = "Jerry" // ✅

// 一开始共享内存，修改时才复制。兼顾性能和安全。
```

* 线程安全

struct: 天然更安全（无共享）

class：容易线程问题，多线程，需要加锁。

**使用场景**

apple官方建议，优先考虑struct，适用于：

* 数据模型
* 不希望继承
* 希望不改变
* 希望线程安全

class适用于：

* 需要继承
* 需要共享状态
* 需要identity

| **特性**   | **struct** | **class** |
| ---------- | ---------- | --------- |
| 类型       | 值类型     | 引用类型  |
| 拷贝       | 复制       | 共享      |
| 内存       | 栈         | 堆        |
| 继承       | ❌          | ✅         |
| ARC        | ❌          | ✅         |
| identity   | ❌          | ✅         |
| 线程安全   | 高         | 低        |
| mutability | let 不可变 | 可变      |



### if a struct is an immutable value type, why we can mutate the size property?

struct本身不是不可变的。struct是值类型，是否可以修改属性取决于你用let还是var声明。当使用var声明时，可以修改属性，这个时候是对整个值的修改；当使用let修饰时，整个值不可变，因此任何属性都不能修改。

```swift
struct Size {
    var width: Int
    var height: Int
}

var size = Size(width: 10, height: 20)
size.width = 30 // ✅ 可以修改

// size是var声明的，所以整个struct实例是可变的，修改width本质是修改整个值。

let size = Size(width: 10, height: 20)
size.width = 30 // ❌ 报错
// let 让整个struct完全不可变，不是某个属性不能变，而是整个struct被冻结。
```

**本质理解**

struct的不可变性是：值语义 + let控制整体不可变。

struct是一整块值，修改值等于修改整块值，如果是let修饰，则整块不能变。虽然语义上说修改值等于修改整块值，但是具体是否创建新的对象，取决于具体的实现细节。也就是copy-on-write的触发机制。是否只有唯一的引用。

**mutaging关键字**

```swift
struct Size {
  var width: Int
  mutaing func increase() {
    width += 10
  }
}
// 告诉编译器这个方法会修改整个struct值。
```



### Swift 的 Copy-on-Write 是怎么实现的

Swift的copy-on-write（COW)是通过值类型 + 内部引用类型 + 引用计数检测实现的。

当数据被多个变量引用时，只有在修改时才进行真正的拷贝。

```swift
var arr1 = [1,2,3]
var arr2 = arr1

arr2.append(4)
// 直觉上arr1和arr2是两个数组（值类型），应该一开始就拷贝。
// 实际上，一开始没有拷贝，两者共享同一块内存，直到append才复制。
```

**核心实现思想**

```swift
// struct + class组合
// 标准库Array是这样设计的
struct Array {
  var storage: _Buffer  // 内部是引用类型
}

class _Buffer {
  var elements: [Int]
}

// Array是值类型，但内部数据是class（引用类型）
// 这样就可以赋值时，只赋值引用（很快），修改判断是否需要复制。

// 使用 isKnownUniquelyReferenced(&storage) 判读触发copy
if isKnownUniquelyReferenced(&storage) {
    // 只有我一个人在用 → 直接改
} else {
    // 有多个引用 → 复制一份再改
}
```

**模拟cow实现**

```swift
class Storage {
    var value: Int
    init(_ value: Int) {
        self.value = value
    }
}

struct MyStruct {
    private var storage: Storage
    
    init(_ value: Int) {
        self.storage = Storage(value)
    }
    
    var value: Int {
        get { storage.value }
        set {
            if !isKnownUniquelyReferenced(&storage) {
                storage = Storage(newValue) // copy
            } else {
                storage.value = newValue // 直接修改
            }
        }
    }
}
// 多个storage共享storage，修改前检查引用计数，如果不是唯一则copy，通过这种方式，既保证了性能，也保证了安全性。
```

**哪些类型用了COW**

* Array
* String
* Dictionary
* Set

**copy-on-write存在问题**

* 性能看起来很便宜，实际上很贵

```swift
var a = Array(0...5)
var b = a

b.append(6)

// 实际发生了什么
1. a 和 b 共享同一块内存
2. b 要修改 → 发现不是唯一引用
3. 分配新内存
4. 拷贝整个数组（6 个元素）
5. 再 append

// 如果是大数据
var a = Array(0...1_000_000)
var b = a
b.append(1)
// 写操作触发整块拷贝，COW把成本从赋值延迟到了写入。
```

* 你以为是值拷贝，其实还在共享

```swift
var a = [1, 2, 3]
var b = a

// a 和 b 指向同一块内存（还没拷贝）,只在b.append(4)才触发拷贝。值语义被延迟实现。
// 通俗理解
你以为已经复印了一份文件
其实只是两个人拿着同一张纸
直到其中一个开始改，才去复印
```

* 多线程不安全（重要）

```swift
var a = [1, 2, 3]

DispatchQueue.global().async {
    a.append(4)
}

DispatchQueue.global().async {
    a.append(5)
}

// 你以为两个线程分别操作自己的副本，
// 实际上
线程 A：检查 → 不是唯一引用
线程 B：检查 → 也不是唯一引用

两个线程同时开始拷贝和修改同一块数据
// 结果：崩溃，数据错乱。核心原因：COW的唯一性判断不是线程安全的。
```

* 大数据拷贝非常昂贵

```swift
var a = Array(0...1_000_000)
var b = a

b[0] = 999

// 你以为只改一个元素
// 实际上，整个数组被复制一遍（100个元素），即使你只改一个字。
// COW是整块拷贝，而不是局部复制。
```

* 循环中性能灾难

```swift
var a = [Int]()

for i in 0..<10000 {
    var b = a
    b.append(i)
}

// 每次循环
1. b = a（共享内存）
2. b.append → 触发拷贝
3. 拷贝整个数组
最终复杂度接近：O(n²)

频繁写操作 + COW = 性能爆炸
```

* 和class混用（最容易踩坑）

```swift
class User {
    var name: String
    init(name: String) { self.name = name }
}

var a = [User(name: "A")]
var b = a

b[0].name = "B"

// 你以为a和b是独立的，实际输出 print(a[0].name) // B ❗
// Array是值类型，但里面的Array是引用类型。数据拷贝了，但是里面的对象没有拷贝。
// COW是浅拷贝容器，而不是深拷贝数据
```

> 写时拷贝通过延迟复制优化了性能，但也带来一些问题，比如写操作可能触发整块数据复制导致性能不可预测，在多线程环境下存在数据竞争，同时它在实现上引入了引用共享，使值语义变成“延迟值语义”，并且在和引用类型混用时可能产生浅拷贝问题。

### What is a Tuple in Swift?

在Swift语言中，元组是一种轻量级的复合类型，它将多个值组合成一个单一的值。元组中的值可以是不同类型的，并且可以通过位置和名字访问。

```swift
let person = ("Tom", 18)
// 按位置访问
person.0 // "Tom"
person.1 // 18

// 命名访问（更推荐）
let person = (name: "Tom", age: 18)

person.name
person.age

// 结构
let (name, age) = person
print(name) // Tom

// 不需要定义类型，可以存不同类型，适合临时数据。
```

| **对比** | **Tuple** | **struct** |

| 功能     | 简单数据  | 复杂模型   |
| 可扩展   | ❌         | ✅          |
| 可读性   | 一般      | 更好       |



### ﬁnal 是什么：

final是Swift中用于防止继承和重写的关键字。final修饰的类不能被继承，final修饰的属性和方法不能被重写。

**基本用法**

* final class:不能被继承

```swift
final class Animal {
}
class Dog: Animal {} // ❌ 编译报错
```

* final method：不能被重写

```swift
class Animal {
    final func speak() {
        print("sound")
    }
}

class Dog: Animal {
    override func speak() {} // ❌ 报错
}
```

* final property: 

```swift
class Animal {
    final var name: String = "Animal"
}
// 子类不能重写
```

**为什么要用final**

* 安全性（设计意图）：这个类或者方法不应该被修改
* 防止误用：如果子类乱改逻辑，可能bug
* 性能优化：编译器知道不能被重写，可以进行静态派发

**和struct关系**

struct天然就是final的，struct = 默认final。class = 继承（除非加final）

**开发建议**

默认 class 都应该是 final，除非你明确需要继承



### String 与 NSString 的关系与区别：

在Swift中，String是一种值类型，而在Objective-C中，NSString是一种引用类型。他们属于桥接类型，这意味着在需要时，Swift可以自动的在这两种类型间进行转换。

**核心区别**

* 类型本质

| **类型** | **String**       | **NSString**      |
| -------- | ---------------- | ----------------- |
| 语言     | Swift            | Objective-C       |
| 类型     | struct（值类型） | class（引用类型） |

* 内存语义

```swift
var s1 = "Hello"
var s2 = s1
s2.append(" World")

print(s1) // Hello ✅
// 不共享数据

NSString *s1 = @"Hello";
NSString *s2 = s1;
// s1,s2指向同一个对象
```

* 可变性

```swift
NSString *str = @"Hello";
// 不能修改
// 如果要改
NSMutableString *str = [NSMutableString stringWithString:@"Hello"];
[str appendString:@" World"];

var str = "Hello"
str.append(" World") // ✅
// Swift用 var/let 控制可变性
```

* API风格

```swift
[str stringByAppendingString:@" World"];

str.append(" World") // 更简洁，现代
```

* Unicode支持

```swift
Swift String
	•	完全基于 Unicode
	•	支持 grapheme cluster（比如 emoji）

NSString
	•	基于 UTF-16
	•	字符长度计算不准确（emoji 会出问题）
```

* 性能

```swift
Swift String
	•	使用 Copy-on-Write
	•	值语义 + 性能优化

NSString
	•	引用类型
	•	依赖 ARC
```

**桥接**

Swift和OC可以自动转换：自动桥接

```swift
let str: String = "Hello"
let nsStr: NSString = str as NSString

let nsStr: NSString = "Hello"
let str: String = nsStr as String
```

**底层本质**

```swift
Swift String：
	•	struct（值类型）
	•	内部可能使用 NSString（桥接优化）

也就是说：Swift String 在某些情况下会使用 NSString 作为底层存储
```

| **特性** | **String** | **NSString**         |
| -------- | ---------- | -------------------- |
| 类型     | struct     | class                |
| 语义     | 值         | 引用                 |
| 可变性   | var 控制   | 需要 NSMutableString |

### defer 使⽤场景：

在Swift中，defer关键字用于在退出当前作用域时，执行一段代码。它通常用于执行一些清理任务。例如关闭资源，解锁或者重置状态。

**基本用法**

```swift
func test() {
    defer {
        print("defer")
    }
    
    print("start")
}
// 输出
start
defer

// 在函数结束时执行，一定会执行，无论return、throw。
```

**核心特性**

* 在当前作用域结束时执行
* 多个defer时，先进后出。

```swift
func test() {
    defer { print("1") }
    defer { print("2") }
    defer { print("3") }
}

// 输出：先进后出
3
2
1
```

* 即使return/throw也会执行

```swift
func test() {
    defer {
        print("cleanup")
    }
    
    return
}
// 输出：cleanup
```

**使用场景**

* 资源释放

```swift
func readFile() {
    let file = openFile()
    
    defer {
        file.close()
    }
    
    // 读取文件
}
```

* 锁的释放

```swift
lock.lock()

defer {
    lock.unlock()
}

// 业务逻辑: 避免忘记unlock，避免死锁。
```

* 状态恢复

```swift
isLoading = true

defer {
    isLoading = false
}
```

* 数据库、网络资源管理

```swift
connection.open()

defer {
    connection.close()
}
```

**注意事项**

* 在作用域结束后执行
* 不能跨作用域：只作用于当前block
* 捕获变量

```swift
var x = 10

defer {
    print(x)
}

x = 20
// 输出20
```



### struct在栈区还是堆区

struct并不一定在栈上，它既可以在栈上，也可以在堆上。具体取决于使用场景和编译器优化。swift中struct的核心是值语义，而不是存储位置。

**什么时候在栈上**

* 局部变量（常见情况）

```swift
struct Point {
    var x: Int
    var y: Int
}

func test() {
    var p = Point(x: 1, y: 2)
}
// p会分配在栈上（更快）
```

**什么时候在堆上**

* 被class持有

```swift
class Container {
    var point = Point(x: 1, y: 2)
}
// Container在堆上，point作为它的属性，也存储在堆上。
```

* 被闭包捕获

```swift
func test() {
    var p = Point(x: 1, y: 2)
    
    let closure = {
        print(p.x)
    }
}
// 此时p可能会被提升到堆上
```

* 编译器优化

编译器可能决定：放堆上（避免栈溢出），或做优化（寄存器等）

* copy-on-write类型

```swift
var arr = [1,2,3]
Array是struct，但是内部数据存储在堆上。
```

struct 不等于栈，class 不等于堆，Swift 的核心是语义（value vs reference），而不是存储位置。



### 属性中，值属性，和计算属性以及懒加载有什么区别？

Swift中常见的属性主要有3种，存储属性，计算属性和懒加载属性，他们主要的区别在于是否存储值、是否实时计算以及初始化时机不同。

**存储属性**

```swift
// 直接存值
struct User {
    var name: String = "Tom"
}

// 有实际内存存储，读写快，不能做复逻辑。
// 本质就是一个变量，占内存。
```

**计算属性**

```swift
// 不存值，每次计算
struct Rectangle {
    var width: Double
    var height: Double
    
    var area: Double {
        return width * height
    }
}
// 不占存储空间，每次访问都会计算，可以封装逻辑，就像一个函数。

// 带getter和setter方法
var area: Double {
    get {
        width * height
    }
    set {
        width = newValue / height
    }
}
```

**懒加载属性**

```swift
// 延迟初始化，第一次使用才创建。
class DataManager {
    lazy var data: [Int] = {
        print("初始化")
        return [1,2,3]
    }()
}

let manager = DataManager()
manager.data // 第一次才执行初始化

// 第一次访问才初始化，只初始化一次，可以优化性能，必须是var。本质是延迟执行的存储属性。
```

| **属性类型** | **是否存值** | **是否计算** | **初始化时机** |
| ------------ | ------------ | ------------ | -------------- |
| 存储属性     | ✅            | ❌            | 创建时         |
| 计算属性     | ❌            | ✅            | 每次访问       |
| lazy 属性    | ✅            | ❌            | 第一次访问     |

**使用场景**

存储属性：基础数据存储（model）

计算属性：派生数据，避免冗余数据

lazy属性：重资源对象（网络、数据和UI），提高性能（按需加载）。



### 泛型理解

泛型是一种允许我们编写与类型无关的通用代码的机制，使代码可以不同类型之间复用，同时保持类型安全。

简单理解：把类型当参数传进去。

```swift
func swap<T>(_ a: inout T, _ b: inout T) {
    let temp = a
    a = b
    b = temp
}
// 这里的T可以是Int、String
```

**泛型的本质**

泛型的本质是：参数化类型 + 编译期间类型检查

```swift
// 参数化类型：Array是一个模版，Int/String是参数
Array<Int>
Array<String>

// 编译期确定类型
在编译期就确定类型，没有运行时类型不安全问题
```

**Swift中用到泛型的地方**

```swift

Dictionary<Key, Value>
```

```swift

```

* 函数泛型


### 闭包的理解

Swift中的闭包（closure）是一种可以被传递和执行的代码块，类似于匿名函数，他可以捕获并存储其所在上下文的变量和常量。

**基本用法**

**闭包的本质**

**闭包的内存问题**

#### Can you explain the difference between weak and unowned references in Swift?

weak和unowned都用于解决循环引用问题。他们都是弱引用（不增加引用计数）。

区别在于：

* weak是可选类型，引用对象被释放后会自动被置为nil
* unowned是非可选类型，假设对象始终存在，如果对象被释放后再访问会导致崩溃

**核心区别**

| **对比**         | **weak**       | **unowned**        |
| ---------------- | -------------- | ------------------ |
| 是否增加引用计数 | ❌              | ❌                  |
| 类型             | Optional       | 非 Optional        |
| 对象释放后       | 自动变 nil     | 变成野指针（崩溃） |
| 安全性           | 高             | 低                 |
| 使用场景         | 生命周期不确定 | 生命周期确定       |

**示例**

```swift
// weak: Person可以存在，apartment自动变为nil，不会崩溃
class Person {
    weak var apartment: Apartment?
}

class Apartment {
    var tenant: Person?
}

// unowned:CreditCard 必须依赖 Customer,Customer 一定存在
class Customer {
    var card: CreditCard?
}

class CreditCard {
    unowned let customer: Customer
    
    init(customer: Customer) {
        self.customer = customer
    }
}
```

**使用场景**

* weak用于生命周期不确定，可能为nil的情况。像闭包中使用频率较高。
* unowned用于生命周期一致，一定不会为nil的情况。典型场景：父子关系



#### What is memory leak ? how to solve?

内存泄露指程序中已经不再使用的内存没有被释放，导致内存一致被占用，最终可能引发内存增长、性能下降甚至应用崩溃。

一句话理解：不用了但还占着内存。

**Swift中的本质**

对象之间互相强引用，导致引用计数永远不为0。

**闭包中的循环引用**

```swift

```

**如何解决循环引用**

* 使用unowned
* 打破循环引用

### Please implement a convenience init method for a subclass.

```swift
class Person {
    var name: String

    init(name: String) {
        self.name = name
    }
}

class Student: Person {
    var grade: Int

    // 指定初始化器（Designated Initializer）
    init(name: String, grade: Int) {
        self.grade = grade
        super.init(name: name)
    }

    // 便利初始化器（Convenience Initializer）
    convenience init(name: String) {
        self.init(name: name, grade: 0)
    }
}
```

**convenience init必须调用同类的init**

```swift
convenience init(...) {
    self.init(...)  // ✅ 必须调用本类的 designated init
}
// 不能直接掉super.init
```

**初始化链规则**

* 指定初始化器（Designed Initializer）必须调用`super.init()`
* 便利初始化器，必须调用`self.init()`

在 Swift 中，convenience init 是一种辅助初始化方法，它必须调用同类中的 designated initializer，而不能直接调用父类的初始化方法。

在子类中实现 convenience initializer 时：

1. 需要通过 self.init(...) 调用本类的 designated initializer
2. 由 designated initializer 负责调用 super.init(...)
3. 整个流程遵循 Swift 的两段式初始化机制

这种设计保证了：

- 所有属性在使用前完成初始化
- 初始化链清晰且安全
- 避免未初始化状态

### KVO的理解

KVO（Key-Value-Observing）是一种观察者机制，用于监听对象属性的变化，当属性改变时自动通知观察者。

**整个工作流**

```swift
// 场景：监听下载进度
class Download: NSObject {
    @objc dynamic var progress: Float = 0
}
// @objc:让swift进入Objective-C runtime，KVO是基于OC实现的
// dynamic: 强制使用动态派发，才能被runtime替换setter方法，如果使用 var progress: Float 静态派发 -> 无法拦截 -> KVO失效

// 整个流程分为5步
// 1. 注册观察
let download = Download()
let obervation = download.observe(.\progress, options: [.new]) { obj, change in 
  print("progress changes:", changed.newValue ?? 0)
}

// 此时系统内部做了什么
- 创建一个隐藏子类: NSKVONotififying_Download
- 把download的isa指针改掉：download → 指向 NSKVONotifying_Download
- 重写setter
setProgress {
    super.setProgress(...)
    通知观察者
}

// 2.属性发生变化
download.progress = 0.5
// 实际上调用的不是原来的setter，而是 NSKVONotififying_Download.setProgress

// 3. setter内部流程
1. willChangeValue(forKey:)
2. 修改值
3. didChangeValue(forKey:)

// 4.系统通知观察者
遍历所有观察者-> 回调closure/block

// 5.执行你的代码
print("progress changed:", 0.5)
```

KVO是基于Objective-C runtime的。本质是runtime动态子类 + 方法重写。

**核心概念**

KVO：监听属性变化的机制

Key：.\progress

Value： 属性的值

Oberving：当值变化时通知你

> KVO 是一种基于 Key-Value 的观察机制，用于监听对象属性变化，当属性发生变化时自动通知观察者。它的底层实现依赖 Objective-C runtime，通过动态生成子类并重写 setter 方法来实现通知机制。KVO 常用于监听系统属性如 contentOffset、estimatedProgress 等，但由于它依赖 Objective-C、使用复杂且存在安全问题，在现代开发中通常被 Combine、SwiftUI 或 RxSwift 替代。

**什么时候使用KVO**

* 监听系统属性（UIKit/AVFoundation)
* 老项目（Objective-C）
* 没有引入响应式框架时
* 新项目优先（Combine/SwiftUI）
* Swift纯模型（不依赖NSObject）

**使用场景**

* UIKit中典型KVO场景

```swift
// 1.UIScrollView滚动：用于下拉刷新、吸顶效果、导航栏渐变
scrollView.observe(\.contentOffset)

// 2.WKWebView加载进度：用于显示进度条
webview.observe(.\estimateProgress)

// 3.视图布局变化：某些动态布局变化场景
view.observe(\.frame)
```

* AVFoundation中的典型场景

```swift
// 1.播放状态
player.observe(\.status)

// 状态变化：unknown → readyToPlay → failed
// ready -> 开始播放
// failed -> 显示错误

// 2. 缓冲进度
playerItem.observe(\.loadedTimeRanges)
// 显示缓冲进度条

// 3. 播放完成
playerItem.observe(\.status)
```

> UIKit 和 AVFoundation 中很多关键属性，例如 contentOffset、estimatedProgress、player status 等，都是由系统内部异步更新的，开发者无法主动控制这些变化。因此需要一种机制在属性变化时自动通知应用，这就是 KVO 的典型使用场景。通过 KVO，可以在这些状态变化时及时更新 UI 或执行逻辑，比如实现滚动监听、网页加载进度和播放器状态管理等。

**KVO问题**

* 容易crash（老API）：没移除observer -> 崩溃
* 强依赖OC： NSObject + @objc dynamic
* 隐式行为：偷偷修改setter方法
* 调试困难：看不到谁在监听
